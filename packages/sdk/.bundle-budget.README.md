# Orçamento de bundle — por que 215000

Subiu de **201000** para **215000** (+7%) no M75. O gate mediu **207514 (103%)** e a causa estava
**declarada antes de existir**: o D1 do plano `m75-sandbox-kernel-no-framework` coloca o confinamento
de kernel (`LinuxSandbox` + argv do bwrap + filtro cBPF, ~600 linhas de stdlib puro) no core do SDK, e
escreveu a consequência — *"consumidor macOS/Windows carrega ~600 linhas no bundle. Aceito."*

O gate está cobrando essa conta. É o trabalho dele, e é por isso que o número não foi subido em
silêncio.

**Alternativa rejeitada (D1), e segue rejeitada:** pacote irmão `@theokit/sdk-sandbox-linux`, análogo
ao `codex-linux-sandbox`. A analogia não transfere — aquele crate existe para isolar `seccompiler`,
`clap` e um binário; aqui o custo de dependência medido é **zero** (só `node:child_process`,
`node:fs`, `node:path`). Criar pacote para isolar zero dependências é cerimônia.

**Gatilho de reversão, inalterado:** se entrar binding nativo ou dependência externa no subsistema de
sandbox, o D1 é superseded pelo pacote irmão e este orçamento volta para 201000.
