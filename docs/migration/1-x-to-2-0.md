# Migrating from `@theokit/sdk@1.x` to `@theokit/sdk@2.x`

> **Status:** SDK 2.0 split is in progress. This guide reflects the **shipped** changes; pending phases are flagged inline.

## Summary of changes

`@theokit/sdk@2.0.0` is a **package split**, not a rewrite. The kernel (`Agent`, `defineTool`, plugin foundation, runtime loop) stays in the same package. Four optional subsystems get pulled into their own publishable packages:

| Subsystem | Old import | New import | Phase |
|---|---|---|---|
| Cache | `@theokit/sdk` | `@theokit/sdk-cache` | ✅ 3 (DONE) |
| Tools | `@theokit/sdk/tools` | `@theokit/sdk-tools` | ✅ 5 (DONE) |
| Memory | `@theokit/sdk` | `@theokit/sdk-memory` | ⏳ 1 (pending) |
| Budget | `@theokit/sdk` | `@theokit/sdk-budget` | ⏳ 2 (pending) |
| Handoff | `@theokit/sdk` | `@theokit/sdk-handoff` | ⏳ 4 (pending) |

The main reason: the barrel of `@theokit/sdk@1.7.0` is **138 KB gzipped** because it re-exports every subsystem unconditionally. After the split, `@theokit/sdk-core@2.0.0` is targeted at **≤30 KB gzipped** — a 78% reduction. Consumers who don't use Cache stop paying for it.

## One-command upgrade (codemod)

The codemod handles 95% of the migration automatically.

```bash
# 1. Update the dep
pnpm add @theokit/sdk@^2.0.0 @theokit/sdk-cache @theokit/sdk-tools

# 2. (when extracted) Add the other subsystems you use
# pnpm add @theokit/sdk-memory @theokit/sdk-budget @theokit/sdk-handoff

# 3. Run the codemod against your source tree
# Dry-run first to preview the diff:
pnpm dlx jscodeshift -t node_modules/@theokit/sdk/node_modules/.bin/sdk-codemod-1x-to-2x \
  src --extensions=ts,tsx --parser=tsx --dry

# Or invoke directly from this repo if you cloned it:
npx jscodeshift -t scripts/migrations/1-x-to-2-0.cjs \
  src --extensions=ts,tsx --parser=tsx --dry

# 4. Apply when satisfied (remove --dry)
npx jscodeshift -t scripts/migrations/1-x-to-2-0.cjs \
  src --extensions=ts,tsx --parser=tsx

# 5. Build + test
pnpm typecheck
pnpm test
```

The codemod:

1. **Splits imports** — `import { Cache, defineTool } from "@theokit/sdk"` becomes two imports (Cache to `@theokit/sdk-cache`, defineTool stays in `@theokit/sdk`).
2. **Rewrites sub-path** — `import { createReadFileTool } from "@theokit/sdk/tools"` becomes `from "@theokit/sdk-tools"`.
3. **Preserves aliases** — `import { Cache as C }` keeps the alias in the new import.
4. **Flags `Agent.create({...})` without `budgetTracker`** — see [Budget tracker](#budget-tracker) below.
5. **Flags `Agent.create({ handoffs: [...] })`** — see [Handoff](#handoff) below.
6. **Idempotent** — running twice produces the same result.

## Before / after by surface

### Cache

```diff
- import { Cache, CacheEmbedderError } from "@theokit/sdk";
+ import { Cache, CacheEmbedderError } from "@theokit/sdk-cache";

  const cache = Cache.semantic({ embedder, threshold: 0.85 });
  const agent = await Agent.create({
    model: { id: "openai/gpt-4o-mini" },
    plugins: [cache.asPlugin()],
  });
```

Runtime behavior identical. Only the import path changes.

### Tools

```diff
- import { createReadFileTool, createListDirTool } from "@theokit/sdk/tools";
+ import { createReadFileTool, createListDirTool } from "@theokit/sdk-tools";

  const agent = await Agent.create({
    tools: [createReadFileTool({ cwd: process.cwd() })],
  });
```

The `@theokit/sdk/tools` sub-path is **REMOVED** in 2.0. The codemod handles this automatically.

### Memory (functional shipped iter 18; Stage 3 source-move pending)

`sdk-memory@0.1.0` ships TODAY with the `MemoryProvider` port consumer
(`createInMemoryMarkdownProvider`). The legacy `Memory` class stays in
sdk-core until Stage 3 source-move completes (iter 30 target).

```diff
+ // NEW (Stage 3 cohort target):
+ import { createInMemoryMarkdownProvider } from "@theokit/sdk-memory";
+
+ const agent = await Agent.create({
+   memoryProvider: createInMemoryMarkdownProvider(),
+   /* ... */
+ });

  // Legacy Memory class still works (sdk-core retains it until Stage 3):
  import { Memory } from "@theokit/sdk";
  const mem = await Memory.openIndex({ cwd: process.cwd() });
```

`createInMemoryMarkdownProvider` provides (iter 33-37 surface):
- Disk-backed session-summary write (`recordSessionSummary` port method)
- Cross-session recall via substring match (`runActivePass` reads
  `${cwd}/.theokit/memory/sessions/*.md`)
- LLM-facing tools: `memory_remember(content)` + `memory_search(query)`
- Multi-agent privacy filter (recall scoped by `args.agentId`)

### Budget (functional + Phase 2 physical Stage 1 shipped iter 18-19)

`sdk-budget@0.1.0` ships TODAY with the `BudgetTracker` port impl
(`createUsdBudgetTracker`) PLUS Phase 2 physical Stage 1 (iter 19) moved
568 LOC of Budget facade primitives (registry / enforcement / ledger /
normalize-usage / calendar-window) from sdk-core into sdk-budget. The
sdk-core copies remain for v1.x sync API back-compat.

```diff
+ // NEW (preferred, USD-cost-aware):
+ import { createUsdBudgetTracker } from "@theokit/sdk-budget";
+
+ const agent = await Agent.create({
+   /* ... */
+   budgetTracker: createUsdBudgetTracker({ maxUsd: 5.00 }),
+ });

  // Legacy Budget facade also still works (sdk-core retains
  // back-compat copies):
  import { Budget } from "@theokit/sdk";
  const budget = Budget.create({ /* ... */ });
```

Codemod (iter 39 entries) rewrites 21+ Budget symbols to sdk-budget
direct imports automatically.

#### Budget tracker — silent breaking change ⚠

Before 2.0: `Agent.create({ /* ... */ })` automatically constructed a Budget instance and tracked usage. Consumers who **never** referenced `Budget` still had enforcement.

In 2.0: `Agent.create({ /* ... */ })` without `budgetTracker` runs **unbounded**. Costs are not tracked, limits are not enforced. The agent emits `console.warn("[theokit] Agent <name> running without budgetTracker — costs are unbounded.")` ONCE per agent instance.

The codemod flags every call site that does not explicitly pass `budgetTracker:` with a `CODEMOD-WARN` comment. Read those comments before merging — silently losing budget enforcement in production is a real risk.

### Handoff (extracted Phase 4 — sdk-handoff@0.1.0 ✓)

```diff
- import { Agent, Handoff } from "@theokit/sdk";
+ import { Agent } from "@theokit/sdk";
+ import { Handoff } from "@theokit/sdk-handoff";

  const billing = await Agent.create({ name: "billing", /* ... */ });
- const support = await Agent.create({
-   name: "support",
-   /* ... */
-   handoffs: [billing],                                    // ← removed in 2.0
- });
+ const support = await Agent.create({
+   name: "support",
+   /* ... */
+   plugins: [Handoff.asPlugin({ targets: [billing] })],    // ← new pattern
+ });
```

#### Handoff option removed

The `handoffs:` option on `Agent.create` is removed in 2.0. Use `Handoff.asPlugin({ targets: [...] })` and pass it via `plugins:` instead. The codemod marks every call site with a `CODEMOD` comment — manual rewrite is required because the transformation is semantically non-trivial.

## Complete list of breaking changes

| # | Change | Detected by | Migration |
|---|---|---|---|
| 1 | `Cache, CacheEmbedderError, CacheInvalidTtlError` moved from `@theokit/sdk` to `@theokit/sdk-cache`. | TypeScript TS2305 "Module has no exported member". | Codemod (B) rewrites imports. |
| 2 | `@theokit/sdk/tools` sub-path removed; consumers import from `@theokit/sdk-tools`. | Module-resolution failure. | Codemod (A) rewrites sub-path. |
| 3 | `Agent.create({ /* ... */ })` no longer auto-creates Budget. | Runtime warn-once + codemod CODEMOD-WARN comment. | Add `budgetTracker:` explicitly OR accept free-run mode. |
| 4 | `Agent.create({ handoffs: [...] })` option removed. | TypeScript TS2353 + codemod CODEMOD comment. | Wrap with `Handoff.asPlugin({ targets })` and pass via `plugins:`. |
| 5 | `Memory` moved from `@theokit/sdk` to `@theokit/sdk-memory` (pending Phase 1). | TS2305 (after Phase 6 cohort). | Codemod will rewrite imports once Phase 1 lands. |
| 6 | `Budget` and related symbols move to `@theokit/sdk-budget` (pending Phase 2). | TS2305. | Codemod rewrite + add `budgetTracker:` to `Agent.create`. |
| 7 | `Handoff` and related errors move to `@theokit/sdk-handoff` (pending Phase 4). | TS2305. | Codemod rewrite + asPlugin migration. |
| 8 | `@theokit/sdk` package renamed to `@theokit/sdk-core` at 2.0.0 (pending Phase 6). | npm deprecation warning. | `pnpm add @theokit/sdk-core@^2.0.0` + remove `@theokit/sdk@1.x`. |

## Rollback procedure

If a release of 2.0.0 misfires, every step is reversible:

1. **Pin the consumer back to 1.7.0:**

   ```bash
   pnpm add @theokit/sdk@1.7.0
   pnpm remove @theokit/sdk-cache @theokit/sdk-tools \
     @theokit/sdk-memory @theokit/sdk-budget @theokit/sdk-handoff
   ```

2. **Revert codemod changes:**

   ```bash
   git revert <codemod-application-commit>
   ```

3. **Confirm everything builds:**

   ```bash
   pnpm install
   pnpm typecheck
   pnpm test
   ```

The `@theokit/sdk@1.x` line stays on npm with a deprecation message (`npm deprecate @theokit/sdk@"<2.0.0" "..."`) pointing at the new package layout, but install still works.

## Known limitations of the codemod

- **Namespace imports** (`import * as SDK from "@theokit/sdk"`) get a `CODEMOD: namespace import` comment — cross-package namespaces don't compose. Switch to named imports and re-run the codemod.
- **Side-effect imports** (`import "@theokit/sdk"`) get a `CODEMOD` comment — the 2.0 split has no side-effect entry point; verify the import is still needed.
- **Unknown symbols** (not in the symbol map) stay in `@theokit/sdk` with a stderr WARN.
- **Aliased re-exports across packages** — `export { Cache as C } from "@theokit/sdk"` rewrites the source but does not re-bucket. Manual cleanup after `pnpm typecheck` may be needed.
