Resume is no longer lossy (#62). (1) **Session hydration** used to filter the rebuilt context to `user`/`assistant` only, silently dropping `tool_call`/`tool_result` turns — a resumed agent forgot every tool it had run. Tool turns are now folded into the hydrated context (as assistant-role context) so the tool history survives resume; legacy user/assistant JSONL loads unchanged. (Exact tool_use/tool_result LLM-block reconstruction for mid-call resume needs persisted tool-use ids — a schema change deferred.) (2) **Workflow resume** used to continue from the suspend point with only the resume payload, so earlier step outputs were lost; the resumed run now restores the snapshot's accumulated step outputs, so a post-suspend step can see prior results. (3) **Scoped session state:** `scopedConversationId(scope, id)` namespaces a conversation id by `app:`/`user:`/`temp:` scope (path-safe `__` separator), and `ConversationStorageAdapter.deleteScope(prefix)` prunes a whole scope (e.g. `temp` on logout) in one call — additive.
